# Plan: Evaluate and Remove EdgePoint/Docker Dependencies

## Goal
Determine whether the EdgePoint CLI (`my-app/edge`) and its Docker stack are necessary for the CaféOS project, or if the project can run fully native via `npm run dev`. Identify which files can be safely removed if the project goes fully native.

## Analysis

### Three execution modes exist

| Mode | How to run | Database | Acceptance tests | Platform |
|---|---|---|---|---|
| **Host-native** | `npm run dev` | SQLite (`prisma/dev.db`) | No (no Playwright browsers) | Any |
| **Docker (EdgePoint)** | `./edge dev` (bash + Docker) | Postgres | Yes (Playwright image) | macOS/Linux only |
| **Electron desktop** | `npm run electron` | SQLite (bundled `dev.db`) | No | Windows/macOS/Linux |

### Key findings

1. **`my-app/edge`** is a bash script — it **does not work on Windows** (no WSL assumed). Native `npm run dev` is already the Windows dev path.

2. **Docker is only needed for acceptance tests** — the `edge` script uses the Playwright Docker image (`mcr.microsoft.com/playwright:v1.50.0-noble`) which includes browsers. Host `npm run dev` uses SQLite, not Postgres. Unit tests run via Vitest natively without Docker.

3. **Production deployment** still requires Docker — `deploy/compose.prod.yaml`, `Dockerfile`, and `deploy/migrate.sh` are referenced by `.github/workflows/deploy.yml` for production deployment. These **must be kept**.

4. **Electron packaging** is independent of Docker — `electron/main.js` wraps the Next.js app and bundles the SQLite database via `electron-builder`. The `electron/` directory and related scripts are unaffected by Docker removal.

5. **Legacy EdgePoint artifacts** — `START-HERE.md`, `CONTEXT_SUMMARY.md` (already deleted), compose files, and the `edge` script were all generated by EdgePoint for a different workflow (edgepoint CLI at `C:\nvm4w\nodejs\edgepoint.ps1`). The project has migrated to SpecKit (`tools/pebot` / `tools/pebot.ps1`).

## Files that CAN be safely removed (EdgePoint-only, no Docker needed)

| File | Reason |
|---|---|
| `my-app/edge` | Bash script, doesn't work on Windows, EdgePoint-specific |
| `my-app/START-HERE.md` | Stale EdgePoint onboarding doc (references `edgepoint` CLI at non-existent path) |
| `my-app/compose.guide.yaml` | Only used by `./edge guide` for test guides |

## Files that MUST be KEPT (used for production deployment)

| File | Reason |
|---|---|
| `my-app/Dockerfile` | Production image, referenced in deploy workflow |
| `my-app/Dockerfile.dev` | Dev container image, used by `./edge dev` and CI |
| `my-app/compose.yaml` | Docker dev stack, used by `./edge` commands |
| `my-app/deploy/*` | Production deployment files, used by GitHub Actions |
| `.github/workflows/deploy.yml` | CI/CD pipeline |

## Decision points (business questions)

1. **Do you need to run acceptance tests (Playwright) on this machine?**
   - If yes → Docker/EdgePoint stack must be kept (requires WSL2 on Windows)
   - If no → the native workflow (`npm run dev`, `npm run test:unit`, `npx tsc --noEmit`, `npm run lint`) is sufficient

2. **Do you deploy via Docker on a Linux server?**
   - The Dockerfiles and deploy files are committed and used by `.github/workflows/deploy.yml`
   - These should be kept regardless of local dev workflow

3. **Do you use the Electron desktop app?**
   - `electron/main.js` and `electron/seed.js` are independent of Docker
   - Should be kept if you distribute a Windows desktop client

## Recommendation

**Keep the Docker files for production** but **remove EdgePoint-only local files**:

1. Delete `my-app/edge` (bash script, unused on Windows)
2. Delete `my-app/START-HERE.md` (stale EdgePoint doc)
3. Delete `my-app/compose.guide.yaml` (only used by `./edge guide`)
4. Keep `my-app/compose.yaml`, `Dockerfile`, `Dockerfile.dev` (used by deploy/CI)
5. Keep all `deploy/` files (used by CI/CD)

Native workflow on Windows:
```bash
npm run dev    # starts server.js on port 3000
npm run lint
npx tsc --noEmit
npm run test:unit
```
