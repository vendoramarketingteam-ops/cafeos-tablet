# Plan: v1.0.4 Bug Fixes & Feature Requests

## Critical Bugs from Console Log

### Bug 1: Ingredient creation — `supplier` field type mismatch
**File:** `app/api/ingredients/route.ts:30` and `app/api/ingredients/[id]/route.ts:42`

The API passes `supplier` (string) to Prisma, but after the schema migration, Prisma expects `supplierId` (integer).
- POST endpoint (route.ts): `supplier: supplier || null` → should be `supplierId: supplier ? parseInt(supplier) : null`
- PUT endpoint ([id]/route.ts): same field `supplier` → should use `supplierId`
- Frontend (app/admin/products/page.tsx:108): `ingredientForm` uses `supplier: ''` (string) → change to `supplierId: null`
- Frontend: ingredient modal should use a supplier dropdown (ID) like the inventory page already does

### Bug 2: Loyalty settings — `categoryId: undefined` crashes `findUnique`
**File:** `app/api/loyalty/settings/route.ts:104-106`

When `targetCatId` is `null`, `targetCatId ?? undefined` returns `undefined`, causing Prisma validation error.
- Fix: Build the `where` clause conditionally — only include `categoryId` when it has a value
- For the create path when `categoryId` is null: skip the existence check entirely
