## Critical Bug: Ingredient Stock Not Syncing on Orders

### Current State
- Orders API POST handler (`app/api/orders/route.ts:196-200`) deducts `Inventory.quantity` (product stock) via `decrement`
- **Bug**: `Ingredient.currentStock` is NEVER deducted when orders are placed
- Inventory API PATCH (`app/api/inventory/route.ts:63-79`) auto-syncs ingredients to product stock capacity, but only on manual product inventory adjustments — not order placements
- Cancel flow (orders PATCH, lines 92-97) restores `Inventory.quantity` but NOT `Ingredient.currentStock`
- Result: ingredient stock levels drift from reality as orders flow in

### Fix
1. **Orders API POST** — After deducting product inventory, also deduct ingredient stock:
   - Query `ProductIngredient` for each ordered product
   - Decrement `Ingredient.currentStock` by `(item.quantity × productIngredient.quantity)`
   - Emit `ingredients-update` socket event
   - All within the same `$transaction`
2. **Orders API PATCH (cancel)** — When restoring inventory on cancel, also restore ingredient stock
   - Increment `Ingredient.currentStock` by the original order quantities
   - Emit `ingredients-update` event

## Feature 10: Fix Loyalty Card sync — Registered Customers Not Visible

Yes — loyalty cards should be created proactively when the customer enters their name at the cart, before they can place an order. Customers must be registered in the loyalty system before ordering.

### Fix
1. **Cart page** — When customer enters their name, proactively fetch/create a loyalty card:
   - Use existing `/api/loyalty/cards/:customerName?categoryId=X` endpoint (auto-creates if missing)
   - Show "Registered as [Name]" status before the order confirmation dialog
2. **Orders API POST** — Also create a LoyaltyCard as a safety net:
   - Use `prisma.loyaltyCard.upsert()` to find-or-create by normalized `customerName` + `categoryId`
   - All within the existing `$transaction`
3. **Shared `normalizeMemberName`** — Extract from the loyalty API's inline function into a shared utility:
   - Used by both the API and `loyalty-award.ts` for consistent normalization
4. **`lib/loyalty-award.ts:94`** — Replace `.trim().toUpperCase()` with the shared `normalizeMemberName`

### Files

## Feature 12: Audit Logs for All Features

### Current State
- No audit logging system exists anywhere in the codebase
- No `AuditLog` model or similar
- User actions (orders, loyalty awards, settings changes) are not tracked

### Plan
1. **Schema** — Add `AuditLog` model:
   ```prisma
   model AuditLog {
     id        Int       @id @default(autoincrement())
     userId    Int?
     user      User?     @relation(fields: [userId], references: [id])
     action    String    // e.g., "ORDER_CREATE", "LOYALTY_AWARD", "SETTINGS_UPDATE"
     resource  String    // e.g., "order", "loyalty_card", "business_settings"
     resourceId Int?
     details   Json?     // Additional context (old values, new values, notes)
     ip        String?
     createdAt DateTime  @default(now())
     @@index([userId])
     @@index([createdAt])
     @@index([resource, resourceId])
   }
   ```
   Add `auditLogs AuditLog[]` to the `User` model.
2. **Utility** — Create `lib/audit-log.ts` with `logAction()` helper:
   - `logAction({ userId, action, resource, resourceId, details, ip })`
   - Easy to call from any API route
3. **API** — Create `GET /api/audit-logs`:
   - Admin-only access
   - Support pagination, filtering by action/resource/date range
   - Returns logs sorted by `createdAt` descending
4. **Admin UI** — Add "Audit Logs" page under Settings:
   - Table with columns: Date, User, Action, Resource, Details
   - Search and filter by action type
   - Pagination
   - Read-only (no create/delete — just for review)
5. **Instrument key actions** — Add `logAction()` calls at:
   - Order creation (`app/api/orders/route.ts`)
   - Order cancellation (`app/api/orders/[id]/route.ts`)
   - Loyalty point awarding (`lib/loyalty-award.ts`)
   - Business settings update (`app/api/settings/business/route.ts`)
   - User creation/deletion (`app/api/users/route.ts`)
   - Inventory adjustments (`app/api/inventory/route.ts`)
